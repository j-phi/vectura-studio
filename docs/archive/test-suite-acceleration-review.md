# Adversarial review of uncommitted test acceleration changes

Read-only review performed 2026-10-11. I inspected the changed source, manifests, workflow, and docs; I did not run a full test command or bypass the shared queue. A tiny `node scripts/test-lane-aggregate.js` probe is noted below. Findings distinguish current blockers from evidence needed before future promotion.

## Blockers in the current change

0. **P0 — Sequential audit refactor leaves tests referencing deleted live runtimes.** In `tests/audit/scene3d-mktick-spacing-tone.test.js:808-859`, each `runtime` is local to the `for (const kind ...)` iteration and is cleaned up before assertions; the former outer `runtimes` map no longer exists. Yet `crumbCount()` at `:1047`, isolation setup and `md5Of()` at `:1425-1436`, and I2 at `:1453-1457` still read `runtimes[...]`. The first of these throws `ReferenceError: runtimes is not defined` after a very expensive setup, so the audit cannot complete. Rework these remaining checks to load/close the needed variant inside the owning test or store only precomputed summaries in `R`, without retaining live windows.

1. **P0 — Full coverage/audit cannot collect the new audit suite.** `vitest.config.mjs:10` includes every `tests/**/*.test.js`, so `npm run test:coverage` loads the three files under `tests/audit/unit/`. Each is an unchanged copy of the old unit test and imports `../helpers/load-vectura-runtime` (for example `tests/audit/unit/scene3d-tone-law-collapse.test.js:1`). From that directory, the import resolves to nonexistent `tests/audit/helpers/`; the helper is at `tests/helpers/`. The top-level `tests/audit/scene3d-*.test.js` copies have corrected paths, so the nested copies also duplicate the expensive suites. Remove the nested copies and keep one corrected audit set. I verified all three nested helper paths are absent with a small Node path probe.

2. **P1 — New CI deadlines are below the documented baseline, without evidence of enough speedup.** `.github/workflows/test.yml:60` limits unit to 20 minutes and `:154` limits coverage to 35 minutes. `docs/test-suite-acceleration.md:10-13` records earlier unit steps at 41–57 minutes and coverage at 58–109 minutes. The new coverage command also includes the relocated exhaustive audits. `.github/workflows/test.yml:185` caps scheduled audit at 90 minutes; `scripts/test-lanes.json:23` caps the same local audit command at 60 minutes, even though it runs `test:ci && test:coverage` serially. On a runner near the documented baseline, these jobs time out before reaching their actual pass/fail result. Measure the new suite, then set bounds above observed execution with a margin; only lower them once current evidence supports it.

3. **P1 — The browser feedback test does not verify geometry reached the canvas.** `tests/e2e/feedback.spec.js:13-25` counts pixels whose alpha is nonzero. `src/render/renderer.js:4912-4922` fills the whole canvas and page background before drawing any layer geometry, so the pixel count is positive even if layer stroke drawing is removed or broken. The engine path/stat assertions can still pass. Sample a region or compare pixels before and after generation (excluding the page/grid background), or instrument a real draw call in the browser; retain the live control/stat checks.

4. **P1 — New-branch pushes silently skip the risk fallback.** `scripts/hooks/pre-push:19-21` appends literal `unknown` for an all-zero remote SHA, while the execution loop at `:43-52` recognizes only `core`, `browser`, and `audit`. A first push therefore runs only the feedback canary, despite the manifest's unknown-path fallback requiring all broad lanes. Expand `unknown` to the fallback lane set before the loop.

5. **P1 — The aggregator can report a green shadow gate while an existing full job failed.** `scripts/test-lane-aggregate.js:15-19` checks only jobs selected by the route. During shadow rollout, all existing full CI jobs still run on each PR, but a docs-only plan expects feedback alone. I ran the aggregator with a docs-only plan, `feedback=success`, and `unit=failure`; it exited 0 and printed `passed expected roster: feedback`. If `lane-gate` is made a required check while full jobs cease being individually required, that failure is hidden. While in shadow mode, require every retained full job in the aggregate or keep each as an explicit required check; switch to routed expectations only with a verified branch-rule transition.

## Promotion and measurement defects (block promotion; current full jobs still protect PRs if required)

6. **P1 — Promotion treats sparse or synthetic rows as twenty complete green changes.** `scripts/test-lane-measure.js:39-58` groups any rows with a SHA, counts a SHA green if its *recorded* rows pass, and accepts `lane: audit` as exact-head full audit evidence. It never requires a complete expected job roster per SHA, checks that the audit row came from a real full audit, validates the row's `evidenceOnly/source`, or ensures the requested `--head` is the latest green revision. Twenty one-row feedback entries plus one arbitrary successful audit entry and class labels can satisfy the guard. Require validated per-SHA roster evidence tied to the plan/current workflow, exact-head success for every full audit component, and complete consecutive runs before promoting.

7. **P2 — Queue wait consumes the claimed 60-second feedback budget, and longer waits disappear from telemetry.** `scripts/test-lane.js:14` starts its clock before the child enters `scripts/test-queue.js`, and `:52-58` kills the process group after 60 seconds even if it is still waiting for the shared lock. That contradicts `docs/testing.md:27` (queue wait separate). The output parser at `scripts/test-lane.js:27-33` only recognizes `N s`, while `scripts/test-queue.js:95-100` and `:468` print `1m 5s` beyond a minute, leaving `queueWaitMs=null` exactly under contention. Start the execution deadline on lock acquisition (or have the queue expose a structured event), and record wait independently.

8. **P2 — The measurement command reports p95 from one or mixed-class sample without the documented minimum.** `scripts/test-lane-measure.js:19-30` reports `p95LaneSeconds` for any positive number of entries, pooling feedback, core, browser and audit, without distinguishing cold setup or checking the 30 comparable observations per class promised by `docs/test-suite-acceleration.md:94-98`. This is useful as raw exploratory data but cannot support the stated p95 target. Emit count and percentile per comparable lane/class; withhold empirical p95 until the minimum and uncertainty requirements are met.

9. **P2 — Local gate and docs disagree about what runs before push.** `scripts/hooks/pre-push:36-52` runs feedback plus every routed core/browser/audit lane, which for shared changes includes full `test:ci` and full coverage; `docs/testing.md:26,37`, `AGENTS.md:38`, and `README.md:31,37` still call the pre-push gate `test:fast`/bounded feedback. The manifest's `audit` lane also contains `test:ci`, duplicating core and browser when the loop has already run them. This can turn an ordinary local push into hours of repeated work and mislead contributors about the installed hook. Align the hook, manifest and documentation with one explicit policy; avoid running broad child lanes twice.

## Positive checks and limits

- Explicit VM profiles preserve index script order and validate listed files; compiled cache keys include source bytes and override source, and return fresh contexts. The loader contract tests cover missing dependencies and changed bytes. Coverage cache-disable detection is implementation-dependent (`tests/helpers/load-vectura-runtime.js:223-225`); verify with an actual queued coverage run before claiming attribution is preserved.
- The top-level moved audit files retain their substantive tests, and the routine tests retain narrower dispatch, alias and mkTick canaries. Their actual mutation sensitivity and runtime still require queued execution after the duplicate-path blocker is fixed.
- The current workflow still launches broad unit/integration/e2e/visual/perf/coverage PR jobs. The routed aggregate is therefore shadow evidence only while those jobs remain required in branch protection; that external required-check configuration was not available in this source review.
