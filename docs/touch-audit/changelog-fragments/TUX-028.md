## Notes for the integrator and Jay
- **app.js touch notice:** only the `TextEditController` host adapter changed (new hooks `getCaretClientPoint`, `panCanvasBy`, `undoRedo`, `handleShortcut`). app.js has no Phase 2 owner.
- **Config touch:** `playwright.config.js` (desktop-chromium `testMatch` now includes `type-tool-desktop.spec.js`) and `package.json` (`test:e2e` runs that spec). Both are outside the lane file list. They carry the D6 desktop-parity proof.
- **Autocorrect reinterpretation:** autocorrect stays OFF (clause 3). The device row "autocorrect suggestion bar" means: no silent replacement occurs, and dictation and emoji insert correctly.
- **Done chip request (TUX-030/031):** the hide-keyboard key keeps the session on purpose. A Done chip in the context bar should call `textEdit.end()`. Exit paths today: tool switch, Escape on a hardware keyboard.
- **Clause 6 / TUX-032 seam:** `_ensureCaretAboveKeyboard` in `text-edit-controller.js` pans through `host.panCanvasBy`. TUX-032 can replace it with a KeyboardInset service.
- **Paste:** in a touch session a native paste into the proxy is a text paste (`insertFromPaste`). Mouse sessions are unchanged.
- **Hardware keyboard during a touch session:** `shortcuts.js` skips TEXTAREA targets, so the controller forwards chords itself. Non-text Ctrl/Meta chords go to `host.handleShortcut`, which calls `ui.handleTopMenuShortcut`. Cmd/Ctrl+A, C, V and X stay native in the proxy. Z and Y use `host.undoRedo`. A mouse or a tap on a tool restores the normal path.
- **Design decision, Ctrl+K and Ctrl+G:** with the proxy focused on a Mac hardware keyboard, Ctrl+K toggles Settings and Ctrl+G toggles the grid. They no longer act as WebKit Emacs-style text edits (kill line, go to next line). This matches the mouse and global path.
- **Layout dependencies found (not TUX-028 defects):**
  - iPhone landscape: the canvas is 44 px high and the context bar text-size input covers the text layer. Test (h) fails there with "no reachable text-layer point (TUX-007 layout dependency)".
  - iPad portrait and iPhone: the Select/Direct/Lasso tool buttons sit under the left panel (`elementFromPoint` hits `.left-panel-section-header`). Tests (g)/(h) fall back to `ui.setActiveTool` when the button is covered.
  - iPhone landscape: `renderer.draw` throws `IndexSizeError` (arc radius < 0) after a tool change with a selected text layer.
- **J7 ledger pending TUX-059.**

## Fix round: app chords while the proxy has focus
- shortcuts.js ignores TEXTAREA targets, so Cmd/Ctrl+S/E/O/K/0 would die in touch or pen sessions with a hardware keyboard.
- The controller now forwards any Ctrl/Meta chord that is not A/C/V/X (Z/Y keep the undo path) to `host.handleShortcut(e)`.
- `app.js` wires that hook to `ui.handleTopMenuShortcut`. If handled, the event is preventDefault'ed and stopPropagation'ed.
- Tests: touch `(l)` on all 8 projects, integration `forwards app chords`.
