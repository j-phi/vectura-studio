# TUX-038: every double-tap action has a tap or long-press path

## CHANGELOG bullet
- **Touch: exact entry and reset work without a double-click.** Tap the value chip of a range to type an exact number. The Ray Length style range (`rangeDual`) now opens two inputs, min and max, on one tap. Each input uses the decimal keypad. A chip whose control goes below zero uses the full keyboard, so a minus key exists. Press and hold a control label for 0.5 s to open a one-item "Reset to default" menu. The hold never resets by itself, and it never starts on the slider band. It covers sliders, ranges, angle dials, selects, the light pad, the Fill Offset and Centerpoint pads, the Mirror panel dials and the Noise Rack rows. A layer double-tap rename now times the two taps with the browser's own event time, so a slow regenerate no longer turns a double-tap into two single taps. The layer menu item "Rename" now opens the rename field (it did nothing before). The Motion Rack drawn curve selects a point on a tap (22 px reach) and edits it with 44 px Add point and Remove point buttons. Scene 3D object names show the "Double-click to rename" hint only for a mouse. The tour step "Draw Rings on the Canvas" says "double-tap" on touch. A click on a control label no longer presses its hidden "changed from default" dot (it reset the control by accident). Mouse behaviour is unchanged: double-click resets, double-click renames, right-click removes a curve point.

## Decisions and deviations (written reasons)
- The legacy `attachValueEditor` stays. Only the `rangeDual` chip uses it, and the `UI.Slider` dual chip cannot edit (`slider.js` `onChipBlur` ignores a dual value; no caller uses `dual: true`).
- The first dual input has `enterkeyhint="next"` (Enter moves to max). The last has `done`. The brief asked for `done` on both. With `done` on the first input a person could not reach max from the keypad.
- Reset-hold is attached inside `slider.js` and `angle-dial.js` (one place) instead of at each panel call site. Selects, the light pad, the colour input, the `rangeDual` row and the text panel pads call `attachResetHold` directly.
- The text panel pad hold resets the whole field (offset or centre, and its max radius). The mouse keeps two separate double-click resets (pad, max slider).
- A tap on a text-panel scrub label starts the scrub drag as before. A hold that stays within 10 px opens the menu. A finger that jitters can still move that value by a few steps before the hold fires; the menu "Reset to default" corrects it.
- No per-row ⋯ reset menu (brief). The label hold is the long-press path.
- Req 3 (Scene 3D object rename): the object page already has a Name field (`.vs3-name-input`) and every object row selects on tap. No new UI. Regression test `rename-paths.spec.js` case 1 passes on the pre-fix tree. The hint title is gated to a fine pointer.
- `rename-paths.spec.js` case 2 was VERIFY-FIRST and FAILED on the pre-fix tree: the layer menu item "Rename" focused a non-focusable span and did nothing. Fixed with `startLayerRename`.
- Pre-existing bug found and fixed: a `<label>` without `for` activates its first labelable child. The "changed from default" dot is a button inside the label, so a click on a modified control's label text reset the control on every pointer. The label now cancels that default.
- Desktop dblclick on a slider track that moves the value does not reset (the first click's commit rebuilds the controls, so the second click lands elsewhere). This exists before TUX-038. The desktop test double-clicks the thumb centre at the mid value.
