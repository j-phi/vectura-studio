# TUX-029 - Text panel has a text-content field

## CHANGELOG bullet
- Text panel: a multi-line "Text" field (`textarea[data-text-content]`, 16 px minimum, 3+ lines, scrolls past that) now sits at the top of the Type tab. It edits the layer live. ## Decision record (A/B)
- Option A: make the existing specimen (`.vtp-spec-text`) the touch field. Rejected. Four defects: (a) one session adds N history entries (400 ms debounce, `pushHist` on every flush); (b) its font is `clamp(fontSize*0.9, 10, 58)` px with fit-to-frame off, so it falls below 16 px and triggers iOS focus zoom (measured 10 px at size 8); (c) the stage is 78 px high with `white-space: pre` and `overflow: hidden`, so it is not multi-line; (d) jitter > 0.05 splits the text into per-character spans, and the whole specimen hides when collapsed.
- Option B (chosen): a dedicated `<textarea data-text-content>` outside the collapsible specimen. The specimen stays as a preview and stays inline-editable on fine pointers (`matchMedia('(pointer: coarse)')`, not `isTouchCapable`, so touchscreen laptops keep mouse behaviour). Both surfaces call one session helper and one mutation op.

## Notes for the integrator and Jay
- **Single mutation op:** `TextEditController.applyText(layer, text, controller)` sets `params.text`, prunes `kernPairs` keys >= length, and clamps the caret of an active session on that layer. It never pushes history and never regenerates. The field first ends any canvas Type session on the same layer.
- **Contract change:** `params.text` now updates on every input event. The regen and formula update run on a 120 ms debounce. Before, text and regen both waited 400 ms. `tests/integration/text-panel.test.js` "rebuild flushes a pending debounced specimen edit" was updated to the new contract (text immediate, regen flushed on rebuild).
- **CSS:** the older rule `[data-ui-skin] #left-panel-content textarea` (id specificity, 11 px) won over a class-based rule in the first run. The TUX-029 block repeats the `#left-panel-content` prefix.
- **iPhone cells:** iPhP cells pass without a mark. iPhL cells carry `test.fail` for TUX-007 (`IndexSizeError` in the redraw after layer creation). Remove the marks when TUX-007 merges.
- **Desktop parity (D6):** 1600x1000 before/after screenshots show only the added Text field. The specimen stays `contenteditable="true"` with a fine pointer (integration test T8).

## Fix round: live canvas session no longer eats the first tap
- **Defect:** focusing the field called `textEdit.end()`. That ran `refreshPanel` (`ui.buildControls()`) inside the focus event. The panel rebuilt and the field detached.
- **Fix:** `TextEditController.end({ refreshPanel: false })` skips that rebuild. The field handler uses it, then calls the panel-local `refresh()` and `renderSpec()`. Other `end()` callers still rebuild.
- **Tests:** integration T6 uses the real controller and a host that rebuilds as `app.js` does. E2E "first tap on the field keeps it focused" runs on all 8 projects plus `desktop-chromium` (mouse, `tests/e2e/text-panel-field-desktop.spec.js`). The test measures the history delta from after the field tap to the blur: exactly 1 (the canvas session keeps its own earlier entry). The new flow passes on iPhL, so it carries no TUX-007 mark.
- **Undo/redo in a focused field:** `changeText` resets `sessionPushed` when `params.text` differs from the text this session last wrote. The next keystroke then starts a new history entry (integration T6b).
