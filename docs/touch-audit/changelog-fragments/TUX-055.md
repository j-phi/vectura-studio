# TUX-055 — Camera-roll images import safely

## CHANGELOG bullet
- Fixed: Importing a large photo (for example a 48 MP camera-roll image) no longer risks a tab crash or a failed Save. Imports are resampled to 2048 px on the long side. Persisted previews (`imagePreview`, `imageSrc`) are re-encoded from the capped canvas. A decode failure (reader error, image error, null canvas context, `getImageData` throw) now shows a "Couldn't load that image" toast and changes nothing.

## Behavior notes (desktop parity, D6)
- The change applies on every platform. Imports above 2048 px are now resampled on desktop too. The blur radius is in raster pixels, so silhouette edge resolution changes for such images.
- Images of 2048 px or less take the old `drawImage(img, 0, 0)` path and stay byte-identical (proven by Test 4 in `tests/e2e/touch/image-import.spec.js`).
- Rasters already saved in `.vectura` `images` payloads are untouched.
- `raster-plane.js` `decodeToStore` now uses the same cap. It only affects legacy saved `imageSrc` values above 2048 px that have no raster payload.
- Why 2048 and not 4096: at 4096x3072, `saveVecturaFile` writes about 11-13 chars per byte and passes the V8 maximum string length (~536.87M chars). At 2048 the string is about 164M chars.
