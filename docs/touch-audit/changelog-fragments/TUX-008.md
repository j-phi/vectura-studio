# TUX-008 Pane defaults per layout class + pane-state controller

## CHANGELOG bullet
- Touch: iPad portrait and phones now start with both side panels closed. On iPad portrait a panel is a drawer above a dimmed backdrop, and at most one drawer is open. Tap the new panel buttons in the header (left: Generator, right: Layers; header band, left of the theme toggle) to open one; tap the dimmed canvas to close it. iPad landscape (below 1280 px wide) keeps both panels docked and open, capped at 260 px (Generator) and 200 px (Layers), so the canvas keeps at least 45 % of the screen. A collapsed docked panel is a 36 px rail. Wider touch screens (13-inch iPad) keep the normal widths. Rotating to portrait closes the drawers once; rotating back restores the docked choice. A panel width saved on desktop is never rewritten. One pane-state controller (`Vectura.UI.Workspace.paneState`) now owns open, close, toggle, backdrop and per-layout persistence. (TUX-008)

## Interface notes for the other units
- `Vectura.UI.Workspace.paneState` = `{ open(side), close(side), toggle(side), isOpen(side), closeAll(), resetForLayout(), layout() }`. `layout()` is `'desktop' | 'touch-wide' | 'tablet' | 'phone'` (the model layout: a fine pointer is `phone` below 640 px, else `desktop`). Pure state machine: `Vectura.UI.PaneState` (src/ui/shell/pane-state.js).
- Classes: tablet open drawer = `.pane-drawer-open`, phone open drawer = `.pane-force-open`, every closed pane = `.pane-collapsed`, docked open = none. `.auto-collapsed` on `<body>` now means phone only.
- Settings keys: `touchWideLeftPaneCollapsed`, `touchWideRightPaneCollapsed` (new, in preferences). Desktop keeps `leftPaneCollapsed` / `rightPaneCollapsed`. Tablet and phone persist nothing.
- Config: `TOUCH_LAYOUT.maxDockedPaneWidth = 260`, `maxDockedRightPaneWidth = 200`, `roomyMinWidth = 1280`, `maxDockedRoomyPaneWidth = 335`. workspace.js pushes the effective caps to `--touch-wide-pane-max` and `--touch-wide-pane-max-right` on every layout pass.
- DECISION (fix round, option 1): the two TUX-042 cells are marked `test.fail()` on touch-ipad-landscape and webkit-ipad-landscape in tests/e2e/touch/inputs.spec.js, annotated "blocked on TUX-012". Caps stay 260 / 200. Remove the annotation when TUX-012 lands (the test turns red if it starts passing). Original conflict: the 45 % floor at 1210 px forces a 200 px Layers pane. The TUX-042 tests `focused field does not shrink after focus` and `value chips do not clip` fail on iPadL (Pens name input 47 px, layer search tap target). They need TUX-012 to move the pen row and the search field overflow into compact forms. The generator pane cannot go below 260 px (250 breaks the TUX-043 slider drag tests).
- Z tokens (tokens.css): `--z-pane 55`, `--z-toolbar 60`, `--z-backdrop 65`, `--z-drawer 70`, `--z-pane-opener 300`. TUX-010 extends the scale.
- Reset View: `expandPanes()` now calls `paneState.resetForLayout()` first (overlay layouts then keep the left pane only), so the controller and the DOM stay in sync. TUX-009 still owns the touch-specific Reset View behaviour.
- TUX-010: `#btn-mobile-pane-left` and `#btn-mobile-pane-right` are the interim tablet openers. They moved into `#app-header` (index.html), are 44 x 44, glyph-only, and sit left of the theme toggle. Restyle and label them. Phones still have no opener except the 40 px sliver toggle.
- TUX-011: the phone backdrop is now z 65. It covers the other pane's sliver and the tool rail, so a phone swap is two taps. The backdrop is owned by the controller (`render()` in workspace.js).
- Out-of-lane edits (minimal delegations): `src/ui/shell/context-bar.js` `restorePane`, `src/ui/ui.js` `resetPanes`, `src/app/app.js` preference snapshot (two keys), `index.html` (script tag, opener buttons moved into the header).
