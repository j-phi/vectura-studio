## Findings from the measurement
- JRN-003 / TUX-019 hold-to-move (j3.move, j4.move, j4.undo, j4.redo): on every touch project a one-finger drag on a SELECTED object pans the canvas and does NOT move the object. Measured: renderer.offsetX/offsetY +58/+33, object params and world bounds unchanged. The steps assert world-space movement plus an unchanged view offset, so a pan-only drag fails them even when a history entry is pushed (self-test (vi)). A history push would not fix this; the fix is the TUX-019 gesture rule (hold-to-move or a drag that starts on the object body moves the object). `j3.move` ledger reason: "JRN-003 the view panned (58,33) instead of the object moving".
- iPhone landscape: all 36 cells (Chromium, WebKit, chrome variant) fail at `boot` with `renderer.scale` -0.074 (TUX-007).
- WebKit iPhP runs `body.phone-layout` (innerWidth 402); Chromium iPhP does not (544). Both fail J1 at `j1.open-layers`, covered by `.toolbar-drag-handle`.
- JRN-010 (rename on a heavy document): J2 fails at `j2.rename-open` on both iPad projects in both engines. Chromium blocks the main thread 0.9-1.8 s per layer tap. WebKit-desktop runs the same document about 20x faster (40-90 ms), under the 350 ms double-tap window, so WebKit loads `journey-heavy-webkit.vectura` (Flowfield 16x, a tap blocks 0.8-0.9 s idle; more load only lengthens it). The pin is deterministic: the rename input does not show within 6 s of the double-tap (a late input over 1500 ms also fails the step). Verified: 12 of 12 cells with 0 ledger mismatches under shared load (`-g 'J2$'` on the 4 iPad projects, `--repeat-each=3 --workers=4`).
- Boot has its own 45 s budget, separate from the 5 s step budget (J2 steps get 20 s). No cell is pinned on "exceeded the 5000 ms step budget".
- The benign `ResizeObserver loop completed with undelivered notifications` page error is noise (same filter as the console). webkit-ipad-portrait J10 no longer fails on it; it now passes.
- Passing cells today: J8 (most projects), J9 and J10 on iPad.

## Fix round (adjudicator rejection)
- j3.move / j4.move / j4.undo / j4.redo assert world movement and held view offset (readState exposes `worldBoxes`).
- `fingerDrag`, `fingerPinch`, `fingerPan` guard the END points too (self-test (v)).
- Step `expects` text now agrees with `expect.history`; a static test enforces it, including the historyLen column of `journey-scripts.md`. j5.close-path asserts history +1. j7.size-type does not assert history (unreachable today) and its text says so.
- The step's own postcondition runs before the generic history/selection checks, so the failure names the real defect.
