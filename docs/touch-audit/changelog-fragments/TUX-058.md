# TUX-058: Touch target and layout audit as a CI ratchet

## CHANGELOG
- Added a touch target and layout audit ratchet: `tests/e2e/touch/target-audit.spec.js` measures 14 metrics per project and state (overflow, probed 44 px and 24 px targets, WCAG 2.5.8, iOS zoom, covered, safe-area, ghost targets, stranded targets, reachable targets, page errors, canvas share, renderer scale) and fails when one gets worse or better than `tests/e2e/touch/target-baseline.json`. Added `npm run test:e2e:touch:audit` and `:full`, a nightly CI job, and a shared core (`tests/e2e/helpers/target-audit-core.js`). `docs/touch-audit/scripts/target-audit.js` is now a thin CLI with `--engine chromium|webkit`.

## Notes for the docs unit and the orchestrator
- RED numbers. The RED totals in requirements section 1.5 and TUX-041 (206 / 204 / 141 / 131) are unique-target bbox totals across 26 states (`summarizeRun()` in the CLI). They do not reproduce per state. The spec counts per state with PROBED hit sizes. Do not edit the requirements doc for this. The commit body quotes the per-state values.
- R1 (baseline matches the tree it guards): TUX-058 merges to `touch/integration` before any product lane. After each lane merge the integrator re-runs `TOUCH_BASELINE=update` on integration HEAD and commits the lowered cells. A product lane merges `touch/integration` (merge only, no rebase) before its ratchet check. It lowers cells only through `TOUCH_BASELINE=update`. Baseline conflicts are resolved by regenerating on the merged tree.
- R2: lanes that rename the ids the openers use (shell lanes: TUX-001 hamburger, TUX-010 pane toggles) update `tests/e2e/touch/target-audit-states.js` in the same commit.
- R3 (interface request to lane G, owner of `docs/touch-audit/device-checklist.md`): add the [DEVICE] rows "real iPhone portrait: window.innerWidth === 402 and no horizontal pan" and "notch and home-indicator bands clear in tab and standalone mode".
- R4: seed the `linux` baseline section from the first CI or nightly artifact in a follow-up commit. Until then CI asserts only the hard failures.
- Waiver rule: `TOUCH_BASELINE=update-any` needs a `TUX-WAIVER:` line in the commit body.
- Recorded, not fixed: WebKit sets `phone-layout` on iPhone portrait and Chromium does not.
- Fix round: every reachable target is probed (no rect >= 44 shortcut). The span is conservative (owned pixels, no +1 cell; hit tests snap to whole pixels, so the probe samples integer coordinates). The pen tool button (31 x 44 under the Layers pane) now counts in `under44` on iPad portrait. The CLI reads `target-allowlist.json`. The audit spec runs with no retries.
- Fix round 2 (adjudicator rejection). Two guards close holes in the ratchet. `stranded` (lower-better, exact) counts rendered targets that are clipped away with no way to bring them into view. Clipping the overflow with CSS now reads as worse, not as a win. `reachable` (higher-better, tol 0) counts on-screen hit-testable targets. Removing or hiding controls now reads as worse. A drop needs `TOUCH_BASELINE=update-any` and a `TUX-WAIVER:` line in the commit body. Item selectors are unique (`:nth-of-type`), and the allowlist selectors must match at most one element. Regression fixtures: `tests/e2e/touch/target-audit-guards.spec.js` (injects both CSS hacks and asserts worse) and the comparator cases in `tests/unit/touch-target-ratchet.test.js`.
- Waiver rule for removing controls: a lane that moves a control behind a menu lowers `reachable` on purpose. It runs `TOUCH_BASELINE=update-any` and puts `TUX-WAIVER: <cell> reachable <old> -> <new>, <reason>` in the commit body.
- Recorded finding: WebKit iPhone portrait strands Insert and Help (`stranded` 2 in every state, baselined). Chromium widens the layout viewport to 544 px, so they are pannable there.
- Determinism: the spec waits for stable geometry (`waitGeometryStable`) before measuring. Two consecutive `--retries=0` runs of the fast subset give identical counts. `canvasPct` moves by up to 0.7 pp between runs, inside the 1.0 pp tolerance.
