## docs/testing.md text (ratchet, update mode, RED protocol)
The static touch guard (`tests/unit/touch-static-guard.test.js`) compares per-file hit counts with `tests/unit/touch-static-guard-baseline.json`.
Keys are `<rule>|<repo-relative file>`. A missing key means 0. A count above the baseline fails and lists file:line. A count below the baseline also fails: "ratchet down: lower <key> to <n>".
Run `VECTURA_UPDATE_TOUCH_GUARD=1 npx vitest run tests/unit/touch-static-guard.test.js` to lower or delete keys. Update mode never raises a count. If a count went up it refuses with "raising requires a hand edit + TUX-WAIVER: line in the commit body". Only an empty or absent baseline may be seeded.
After merges, regenerate the baseline with update mode. Do not hand-merge it.
Test names (use `-t`): `contextmenu without TouchHold` (R1), `mouseenter-only open` (R2), `mousedown without pointerdown` (R3), `pointerup without pointercancel` (R4), `dblclick without touch alternative` (R5), `html5 dnd without pointer reorder` (R6), `no bare 100vh` (R7), `hover-only reveal outside (hover: hover)` (R8), `icon-only button without aria-label` (R9), `raw modifier flags outside the helper` (R10), `raw range input outside slider` (R11), `drag handle without touch-action none` (R12), `opt-out cap` (R13).
Opt-outs: `// touch-ok: <reason>` (reason must match `/TUX-\d{3}|Q\d+/`, max 10 in total) on the match line or the line above. `// touch-alt: TUX-nnn <text>` declares a touch alternative (max 25 in total).

**RED protocol for consuming lanes (add to §0 and §3 of the requirements, and to docs/testing.md):**
To observe RED for your rule, lower its baseline key to the target value first, run the named test, record the failure, then fix the source.

## Detector decisions
- R7 counts only `100vh`. Partial values such as `60vh` are not counted (decision). `var(--x, 100vh)` fallbacks are excluded. A later same-property declaration with dvh/svh/lvh in the same rule satisfies it.
- R3 counts every `mousedown` registration (no per-module pairing). The `new MouseEvent('mousedown')` bridge in ui-touch.js is not a registration. Array and forEach event-name forms count.
- R9 scans `index.html` only. JS-created buttons are out of scope here. They belong to the TUX-058 runtime audit.
- R10 exclusion heuristic is in the header of `touch-static-guard-rules.js`. Raw reads 178 (69 in shortcuts.js). After exclusion 56 (R10 key reads count only on the handler event object, so petal-designer hit.which no longer excludes pointer reads).
- R12 reads the `bridgeSelector` string literal from `src/ui/ui-touch.js` (parsed, not hard-coded) and adds `.ctxbar-handle`. Key: `R12|src/ui/skin`. 9 classes have no `touch-action: none` rule today.
- R1 is compliant when the file references the `TouchHold` identifier or carries a `touch-alt:` comment. layer-context-menu.js is already compliant on touch/integration (TUX-034 landed), so R1 flags 2 files today (harmonograph-motion-rack.js, canvas-context-menu.js).
- R2 pairs by target (a click/pointerup/pointerdown on the same receiver, or a nearby `touch-alt:`). Today: src/ui/shortcuts.js = 1 (TUX-035, algoParentItem), src/ui/ui-pattern-designer.js = 1.
