# TUX-032 - Fields and sheets stay above the on-screen keyboard

## CHANGELOG bullet
- Touch: fields and sheets stay above the on-screen keyboard. A new `Vectura.KeyboardInset` service publishes `--kb-inset`, `html.kb-open` and a `vectura:kbinset` event. A tap on a numeric field selects its whole value, so typing replaces it. The font picker no longer opens the keyboard on a finger tap. The Save Preset sheet lifts above the keyboard.

## Interface requests and notes
- **Integrator (index.html):** one tag `src/ui/keyboard-inset.js` after `ui-touch.js`, before `ui-text-panel.js`. It is a separate commit (`chore(touch): TUX-032 load keyboard-inset.js`). Keep it when merging.
- **Controls lane:** `pens-panel.js:211` focuses and selects the pens palette search on open. On touch or pen that raises the keyboard on a tap. Branch on `Vectura.KeyboardInset.lastPointerType()` (or the opening event's pointerType). Not edited here.
- **Modal lane (TUX-046 Sheet, TUX-049):** keep consuming `--kb-inset`. The coarse `.vectura-modal-backdrop` gets `padding-bottom: var(--kb-inset)` and `.vectura-modal` gets `max-height: calc(100% - 8px)` while `html.kb-open` (block `TUX-032: keyboard inset` at the end of components.css). Do not add a second visualViewport reader. `tests/unit/keyboard-inset-single-source.test.js` fails if one appears.
- **Shell lane (TUX-002):** any scroll-lock guard must skip while `html.kb-open` or an editable has focus, and must never reset the scroll of an inner container. KeyboardInset pans only inner scroll containers. It never scrolls the document.
- **TUX-028:** `text-edit-controller.js` no longer reads visualViewport. It listens for `vectura:kbinset` and reads `KeyboardInset.inset`. The `text-edit-proxy` integration test follows the new contract.
- **Config:** `playwright.config.js` desktop-chromium `testMatch` now includes `keyboard-inset-desktop.spec.js` (D6).
- **Font search size:** on coarse pointers `.vtp-fp-search input` is 16 px so iOS does not zoom (a zoomed page reads inset 0).
- **iPhone pane opening:** iPhone panes are not finger-openable before TUX-010. The specs open the left pane through the pane DOM state. This is not journey proof.
- **Layer search:** `#layer-search-input` case is `test.fixme` until the layer search bar is finger-reachable.
