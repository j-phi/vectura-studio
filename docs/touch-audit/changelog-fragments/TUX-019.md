# TUX-019: One-finger drag moves objects at once

## CHANGELOG
- A one-finger drag that starts on a selected object (Select tool) now moves it as soon as the finger travels 6 px. There is no 350 ms hold, no haptic buzz, and the view never pans with one finger. A drag that starts on an unselected object selects it and moves it. A drag on empty canvas draws a marquee, as before. A tap with less than 6 px of travel is a select; on a multi-selection it makes the tapped member the Key Object, as a mouse click does. In Direct Selection, an anchor or handle waits for the same 6 px before it moves or adds an undo step. A cancelled touch (`pointercancel`) during a move restores the object and adds no undo step. Mouse and Apple Pencil keep 0 px slop. New config `UI_CONSTANTS.TOUCH_GESTURE.touchDragSlopPx` (6). Removed `touchHoldTimer`, `touchHoldPending`, `clearTouchHold()` and `navigator.vibrate(30)`. Fixes IPAD-006, IPH-027, CODE-024.

## Interface note for the menu lane (TUX-034, canvas long-press)
- `renderer.touchSlopCrossed` is `true` from the moment a one-finger drag crosses the 6 px slop (object move or Direct anchor/handle edit) until lift. The renderer also dispatches `document` event `vectura:touch-slop-crossed` once per crossing.
- Crossing the slop must cancel any pending canvas long-press timer.
- A long-press that has already fired must block a move until lift: do not let a drag start from a finger that opened a menu.
- A second finger is already handled: use `touchArbiter.onSecondFinger()` (TUX-017).

## Notes
- Fix round (thin objects): a touch press arms the move when it hits (via `findLayerAtPoint`, tolerance max(5 px, 2x stroke)) a layer in the selection, as well as when it is inside the strict selection bounds. A finger 2 px off a zero-height line or 3 px off a rectangle outline now moves it. This is touch-only: mouse and pen keep the strict `pointInBounds` test, so a mouse press 2 px off a horizontal line still does not move it (guarded by the "mouse parity" desktop test). On a selected line the edge-midpoint resize zone (10 px) and the outside-corner rotate zones (28 px) still take priority over a move, as for any selected object. TUX-023 `hitTolerance()` was not in the tree; it can replace the `findLayerAtPoint` tolerance later.
- Slop is read from `TouchGestureArbiter.readConfig().touchDragSlopPx`, which falls back to 6 when the config key is missing. `_touchMovePending` replaces `touchHoldPending` in `INTERACTION_FLAGS`, so a second finger inside the arbitration window rolls back a pending or just-started move.
- Direct Selection anchors measure from the original press point after the slop (a grab offset is recorded), so the anchor does not jump by the slop distance.
- Touch + Alt (modifier bar) duplicate-drag now starts after the slop, not at touch-down.
