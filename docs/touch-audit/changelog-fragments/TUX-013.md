# TUX-013 one-row tool rail

## CHANGELOG bullet
- Touch: the tool rail is now one row with a pinned `⋯` All Tools overflow. Tablet portrait rail is 61 px tall (was 204). Phone rail is 52 px tall (was 254). Canvas gains 143 px on iPad portrait and 202 px on iPhone portrait. The slots on the rail come from `Vectura.TOOL_RAIL` (`src/config/tool-drawer.js`). Other tools stay in the All Tools drawer. ## Lane proposal: requirement wording (for the orchestrator or Jay to ratify)
No adjudicator amendment exists in docs/touch-ux-requirements.md or docs/touch-audit. The text below is what this lane implemented. TUX-013 R4 on touch-wide (pin/home visibility) is deferred to TUX-016.
- R1: tablet-layout rail is one row, <= 64 px. Phone-layout portrait rail is one row, <= 52 px (border counted). Phone landscape belongs to TUX-007. The shared rule gives <= 52 there; the guard test asserts it.
- R2: priority-plus, no hidden scroll. `#tool-overflow-btn` is pinned at the trailing edge. The rail has no horizontal scroll.
- R3: no rail child is wider than 50% of the rail. Dividers are 1x24 on tablet and hidden on phone.
- R4: hiding of handle and footer is scoped to phone-layout and tablet-layout + touch-ui. touch-wide and desktop keep them.
- R5: active tool in overflow sets `.active` and `aria-pressed="true"` on `#tool-overflow-btn`.
- R6: the rail adds no top safe-area inset in these layouts.

## Fix round additions
- Collapsed-pane slivers: after a finger collapses a pane on tablet or wide-phone layouts, the 40 px slivers (z 55) overlay the rail ends. The TUX-013 block now insets the rail's inline padding by the sliver width (`body.touch-ui.tablet-layout`, `body.phone-layout:not(.auto-collapsed)`). Narrow phones (`.auto-collapsed`) keep the existing z 60 lift. The e2e now closes panes by finger taps and asserts `elementFromPoint` for every rail button and the overflow button (iPadP, iPhP, iPhL; both engines).
- Algorithm picker on phones: `algo-draw` is off the phone rail. The All Tools drawer item "Draw Algorithm" now opens `#algo-draw-picker` (centred, clear of the rail) when the slot is hidden (`ui._openAlgoPicker`). The ui-tutorial step falls back to `#tool-overflow-btn` as its target when the slot is hidden. Tested finger-only on iPhP: pick `rings` sets `renderer.algoDraftType`.
- TUX-014 reconciliation: `tests/e2e/touch/toolbar.spec.js` TUX-014 surface tests skip a surface whose rail parent is `.rail-overflowed` (reason named in the skip: TUX-013 overflow). The drawer routes are covered by the TUX-013 reachability and picker tests.
- Fine-pointer narrow windows (deliberate): `phone-layout` is keyed on layout class, so a 500 px fine-pointer window gets the phone rail (one row, 6 slots, no footer). 800x900 fine pointer (mobile-layout, no phone/tablet touch-ui) is unchanged. Covered by desktop-chromium tests in `tests/e2e/tool-drawer.spec.js`.
- Stale state: `toolbar.js` observes the body class list and re-runs `applyRailPriority`, so `workspace.expandPanes` (Reset View, fine pointer) clears `.rail-overflowed` and the overflow `aria-pressed`. Tested on desktop-chromium.

## API
- `Vectura.TOOL_RAIL = { phone: [...], tablet: [...] }` in `src/config/tool-drawer.js`.
- `Vectura.UI.ToolDrawer.syncRailState()` updates the overflow pressed state.
- Hidden rail slots get `.rail-overflowed` on the top-level rail child. The DOM stays, so shortcuts and the TLD-2 cross-highlight still work. The cross-highlight marks `#tool-overflow-btn` for a hidden slot.
