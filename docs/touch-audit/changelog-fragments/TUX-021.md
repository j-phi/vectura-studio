# TUX-021 - Apple Pencil takes priority over a resting palm

## CHANGELOG bullet
- **Apple Pencil priority (TUX-021):** an Apple Pencil pointerdown now takes the canvas from a resting palm. The palm's pending Pen-tool anchor, selection change, move, marquee, lasso, scissor or scene drag rolls back by snapshot (no history entry), and a palm pinch/pan stops with the view restored. Palm contacts that land while the Pencil is down start nothing and stay ignored until they lift. A late palm pointercancel no longer aborts the Pencil stroke. Mouse behavior is unchanged.

## Notes
- R2 (view restore on a palm pinch when the Pencil lands) is a delegated default: "palm pinch is accidental". Jay may override.
- Proposed section 5.3 edge: "018 -> 021 (pointerId-scoped abort)".
- TUX-017 policy note: "pen exception to req 1/5" (a Pencil pointerdown rolls back a touch interaction and is not itself latched out).
- TUX-045 (touch modifier latch) is not on this base. Neither the renderer nor `getModifierState` consumes a one-shot latch for a palm, so the "palm does not use up the latch" check (R6) has no code to guard yet. Re-check when TUX-045 lands.
- The pre-gesture view snapshot reuses `renderer._tapViewSnap` (set on the first finger down, TUX-020) instead of a second copy in the arbiter.

## Device checklist (iPad + Pencil)
- One palm contact resting first, then draw a Pen-tool path with the Pencil.
- Two or more palm contacts resting first: the view must not jump when the Pencil lands.
- A palm lands mid-stroke: the stroke is unbroken.
- iPadOS system palm rejection sends a late pointercancel for the palm: the stroke survives.
