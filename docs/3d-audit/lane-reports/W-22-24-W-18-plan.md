## 0. The governing rule (read this before anything else)

**Nothing is ever removed from the engine. Only the picker's flat option list shrinks.**

`src/core/scene3d/surface-fill.js` already accepts a vocabulary far larger than the 48-law roster (it dispatches
`contFieldEase`, `bundleWhole`, `nestedSerpentine`, `weightPlusSpacingTuned`… — study ids that were never
promoted to the roster). The roster (`Vectura.SCENE3D_TONE_LAWS.IDS`, 48 ids) is a *curated subset* that three
gates validate against:

| gate | file | what it does |
|---|---|---|
| curved fill | `surface-fill.js` `buildObject` → `const TONE_ALGO` (~:1440-1443) | `opts.toneLaw` must be in `IDS`, else falls back to `'ladder'` |
| faceted fill | `scene3d.js` `facetedToneLaw` (~:1030-1036) | same membership test, else `''` |
| style clamp | `params.js` `clampStyleParam` `case 'toneLaw'` (~:715) | not in `IDS` and not `DEFAULT` ⇒ warn once + `'ladder'` |
| shadow clamp | `shadows.js` `clampToneLawId` (~:541) | same |

**Therefore the collapse is implemented as a resolver, not a deletion.** `IDS` stays at 48 — the *engine
vocabulary*. A new `PICKER_IDS` (the survivors) is what the UI offers, and a new `ALIASES` table maps each folded
id onto `(survivor, styleParams)`. A one-line resolver turns `(survivor, styleParams)` back into the exact legacy
internal id at each engine boundary.

Consequences, all of them good:

1. **Byte-identity is guaranteed by construction** — the same code path runs. The RGR oracle is exact and needs
   no pinned fixture: both `toneLaw:'fineLadder'` and `toneLaw:'ladder' + rungMode:'fine'` are live in the *same*
   build, so a single test can assert they render identically. Mutation-sensitive: a wrong mapping fails loudly.
2. **`surface-fill.js` and `surface-fill-mono.js` are NOT touched in Phase 1.** That is why Phase 1 does not wait
   for W-26 (in flight on `fill-audit-a`), and why lane contention is small.
3. **No `.vectura` can break.** Every folded id still resolves; the migration only *rewrites* it to the survivor
   form so the picker can show the right row.
4. **The audit's "byte-identical" language must not be trusted blindly** — see §1.1. Several clusters are
   *near*-duplicates with materially different ink. The resolver design makes that irrelevant (the internal id is
   preserved), but a naive "alias `contFieldFore` → `contFieldSigmoid`" rename would have silently changed
   pictures. Do not shortcut to a rename.

## 2. The migration contract

### 2.1 What the data looks like after the collapse

`docs/tone-laws/laws.json` is **NOT edited.** It is the measured corpus and its git blob sha is the drift oracle
baked into `SCENE3D_TONE_LAWS.VERSION`; rewriting it to claim a measured law does not exist would break the
`docs/tone-laws/` gallery and destroy that oracle. This is a deliberate deviation from W-22's wording — record it
in the U0 report. The collapse table is **hand-curated in `scripts/build-tone-laws.js`**, beside the existing
hand-curated `LABELS` and `LIBRARY_IDS` blocks, which is exactly the precedent that file sets for
presentation-tier decisions.

`scripts/build-tone-laws.js` gains one table and emits three new exports:

```js

// engine vocabulary (IDS) is unchanged; only PICKER_IDS shrinks.

  ladder: [{                                   // C-01 (W-22)
    key: 'rungMode', label: 'Rung detail', default: 'coarse',
```

### 2.2 The resolver — one function, one home

`src/core/scene3d/params.js`, exported on `Vectura.Scene3D.Params`:

```js
// (survivor id + its collapse params) → the INTERNAL surface-fill law id.
// Returns the input id unchanged when the style declares no collapse params,
// so every non-collapsed law is a pure pass-through and byte-identical.
Params.resolveToneLaw = (styleParams) => { … };
```

Rules it must obey:
1. `styleParams.toneLaw` absent/unknown ⇒ return `''` / the caller's existing fallback. Do not change the
   existing degrade behaviour of any call site.
2. An **alias** id arriving here (a doc that skipped normalize) ⇒ resolve it directly to its own internal id.
   Never warn. This is the belt to §2.3's braces.
3. A survivor with a collapse descriptor ⇒ look up the option whose `value` matches
   `styleParams[descriptor.key]`; missing/unknown value ⇒ the descriptor's `default` option. Return its `law`.
4. Multi-param survivors (only `contFieldSigmoid`, U5) match on **all** descriptors; an unrepresentable
   combination falls back to the survivor id itself. Deterministic, no throw.
5. Pure function, no DOM, no console, safe when `Vectura.SCENE3D_TONE_LAWS` is absent (bare test process) —
   then it is the identity function.

**Call sites (Phase 1 — three lines total):**

| file | anchor | change |
|---|---|---|
| `src/core/algorithms/scene3d.js` | `toneLaw: sp.toneLaw,` (~:3099, curved `buildObject` opts) | `toneLaw: P.resolveToneLaw(sp),` |
| `src/core/algorithms/scene3d.js` | `facetedToneLaw` (~:1030-1036) | resolve before the `IDS` membership test |
| `src/core/scene3d/shadows.js` | `const toneLawId = clampToneLawId(cfg.toneLaw);` (~:2203) | resolve from the shadow bag first — **see §2.4** |

`surface-fill.js` (~:1440) and `surface-fill-mono.js` are **not touched.** Do not "tidy" the resolver into
`buildObject`; that is the W-26 lane's file.

### 2.3 What a saved `.vectura` or preset does

**Storage form after migration:** `style.params.toneLaw` holds the **survivor** id and the collapse param sits
beside it (`{ toneLaw: 'ladder', rungMode: 'fine' }`).

**The shim** lives in `src/core/scene3d/params.js` in `normalizeStyle` (the function that sees the whole params
bag — `clampStyleParam` clamps one key at a time and cannot write siblings):

```
if (ALIASES[bag.toneLaw]) {
  const a = ALIASES[bag.toneLaw];
  bag.toneLaw = a.into;
  for (k of keys(a.params)) if (bag[k] === undefined) bag[k] = a.params[k];   // never overwrite an explicit value
}
```

Document it exactly the way `HIGHLIGHT_TREATMENT_ALIASES` (`params.js` ~:619, `keep` → `none`) is documented, and
for the same reason: **no `SCENE_MIGRATIONS` step and no `SCENE_VERSION` bump.** No structural shape changed;
`sanitizeSceneParams` on a payload with no `sceneVersion` must still return `4`.
`tests/unit/scene3d-tone-law-params.test.js` assertion 5 already pins that — it must stay green untouched.

**Belt to that brace:** extend `clampStyleParam` `case 'toneLaw'` (~:715) to map an alias id to its survivor and
**not** call `warnUnknownToneLaw` for it. This covers single-key paths — notably
`shadowToneLaw: clampStyleParam('toneLaw', src.shadowToneLaw)` (~:900) — where the sibling params are not
visible. On that path the alias's params are lost; that is only safe because of §2.4, which is why §2.4 is
mandatory, not optional.

**Picker round-trip:** `SCENE_FILL_STYLES.resolve(value)` (`context-bar.js` ~:236) must map an alias to its
survivor so an old doc selects the right row instead of falling back to `ladder`.
`SCENE_FILL_STYLES.entry(id)` must keep answering for alias ids (it reads `BY_ID`, which is unchanged).

**Shipped presets: zero exposure.** Verified on `main` @ `236e2581`:
`grep -rl "toneLaw" user-presets/` → **0 files**; `grep -rlE "fineLadder|whiteBand|bundleCount|contField|penInterleave|weaveDepth|perceptualRamp|taperedEnds|nibAngle|weightSmoothstep|onePenDown" user-presets/ src/config/user-presets.js` → **0 files**. No shipped preset names any fill style. `npm run user-presets:bundle` is therefore **not required** — but U0 must re-run both greps in its own worktree and paste the `0` into its report, and must run the bundler *only* if a preset file actually changed (it must not).

**Forward compatibility is not offered** (and never has been in this codebase): a *newer* file opened by an
*older* build gets `toneLaw:'ladder'` plus an unknown `rungMode` key it ignores, i.e. plain Ladder. State it in
the CHANGELOG; do not build machinery for it.

### 2.4 The shadow path is the trap — do not skip it

`src/core/scene3d/shadows.js` carries an **independent per-law recipe table**, `HATCH_LAW_RECIPES` (~:855),
keyed by *law id*, not by mark class — `shadowMarkLines(rings, angle, spacing, markClass, toneLawId)` (~:2223).
Every folded id has its own recipe: `fineLadder → hatchOffset(…, 0, 0.97)`, `phaseFineLadder → (…, 1.2, 0.97)`,
`perceptualRamp → (…, 0, 1.05)`, `whiteBand → hatchDoublePass(…, 0.5)`, `bundleDither → (… jitterMm …)`,
`contFieldFore → (…, 1.6, 1)`, `penPitchMatch → (…, 0, 1.15)`, and so on.

If the alias shim rewrites `shadowToneLaw:'fineLadder'` to `'ladder'` without resolving, the shadow silently
takes `ladder`'s deliberate *fallback* (plain `hatchRingsEvenOdd` — `ladder` is intentionally absent from the
table) and **every saved scene's shadow texture changes.** That is a real regression the object-path tests would
not see.

Fix, one line at `shadows.js` ~:2203: resolve `(toneLaw + collapse params)` from the shadow bag through
`Params.resolveToneLaw` before `clampToneLawId`, so the recipe lookup receives the internal id. This requires the
shadow bag to carry the collapse params — check `normalizeParams` ~:900 and add the collapse keys the same way
`shadowToneLaw` is added. **U9 owns this and must run last in Phase 1**, because its uniqueness sweep depends on
the final `PICKER_IDS`.

Two invariants that make the rest of the shadow surface safe, and that U0 must assert as tests:

* **Mark class is constant within every cluster.** Verified against `FILL_STYLE_MARK_OF` (`context-bar.js` ~:122):
  C-01 all `hatch`; C-02 all `hatch`; C-03 all `hatch`; C-04 all `hatch`; C-05 all `hatch`;
  C-06 `penInterleave`/`penPitchMatch`/`penFacing` all `hatch` (`penStipple` is `dot` — the one exception, see U6);
  C-07 both `wave`; C-08 both `wave`. Assert: `markClass(alias) === markClass(alias.into)` for every alias.
* **Ribbon-ness (`STROKE_FILL_RIBBON_LAWS`, `context-bar.js` ~:460) is constant within every cluster**, so
  `STROKE_FILL_STYLES.disabledNote(survivor)` is stable and the Stroke Fill row does not flicker between
  enabled/disabled as the collapse param changes. Assert it.

`TONE_LAW_NOT_DISTINGUISHABLE` (`shadows.js` ~:614) contains `isophoteWidth` and **`onePenDown`** — `onePenDown`
becomes an alias in U8. Once folded, the shadow picker's filter must exclude the *combination*
(`interlockWeave` + `penDown:'continuous'`), not the bare id. U8 and U9 must handle this together; the simplest
honest answer is: the shadow Fill Style row does not offer the `penDown` sub-control at all (the shadow footprint
has no pen-down economy to express) and pins `penDown:'perRuling'` for its own resolve. Say so in the (i) note.
