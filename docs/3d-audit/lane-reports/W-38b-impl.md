# W-38b — fix T1's permanently-vacuous `git show HEAD` leg — implementer report

Lane: fill-audit-3 (`.claude/worktrees/fill-audit-3`, port 8476).

## What was wrong (from `docs/3d-audit/lane-reports/W-38-review.md`, Follow-up 1)

`tests/unit/scene3d-facet-min-rulings.test.js`'s T1 built a `preFixV` runtime
in `beforeAll` by loading `scene3d.js` from `git show HEAD:...`, on the theory
that `HEAD` was still the pre-W-38 tree while the work was uncommitted. Once
`575f886d` landed, `HEAD` **is** the post-fix tree, permanently — the leg
compares the current runtime's output to itself, forever. It can never fail,
regardless of any future regression. The reviewer independently confirmed
`diff <(git show HEAD:scene3d.js) scene3d.js` was byte-identical in the
pinned worktree, and recommended fix-or-remove as a required follow-up (not a
rejection of W-38 itself, whose other two proof channels — the real
`426cc5e4` RED reproduction and T10's mutation guard — were already
non-vacuous).

## What changed

`tests/unit/scene3d-facet-min-rulings.test.js` only:

- Removed `execFileSync`/`child_process`, the `preFixRuntime`/`preFixV`
  `beforeAll`/`afterAll` plumbing, and the `git show HEAD:...` leg entirely.
  `SCENE3D_REL`/`ROOT_DIR` are kept — T10's mutation guard still reads the
  live disk source via `fs.readFileSync(path.join(ROOT_DIR, SCENE3D_REL))`,
  unrelated to the removed leg.
- T1 now asserts two legs instead of three:
  1. **Four-origin no-op** (kept, unchanged in spirit): `md5(key absent) ===
     md5(explicit 3)` — the algorithm's own
     `finite(styleParams.facetMinRulings, FACET_MIN_RULINGS)` fallback must
     agree with an explicit 3, same runtime, same run.
  2. **NEW — pinned golden fingerprint** (`EXPECTED_T1`, 60 literal sha256
     hashes, one per T1 fixture): `pathSignature(absent.paths)` (from
     `tests/helpers/path-signature.js`, precision 4 — the exact helper and
     precision `scene3d-hlr-spatial-index-identity.test.js` already uses for
     this identical "golden baked-in hash" pattern) must equal a fixed
     literal recorded now. Unlike the removed leg, this reference is a
     string constant in the file — it cannot become "the same code as the
     runtime under test" just because a commit lands.
- Did **not** attempt to pin at the file's original 9-decimal
  `md5PathsAll`/`toFixed(9)` precision. `1193cbe1` (`test(scene3d): round
  byte-identity/golden comparisons to fix arm64 vs x86_64 CI drift`, 2026-09-
  07) found real last-2-digit floating-point drift between this dev machine
  (arm64) and GitHub's `ubuntu-latest` (x86_64) runner in exactly this kind
  of trig/matrix-heavy scene3d hash comparison, and fixed four other
  byte-identity guards by switching to `pathSignature`'s 4-decimal rounding.
  Pinning literals at 9-decimal precision here would reintroduce that same
  class of false-CI-failure risk the moment this suite runs on a different
  architecture than this session's. Used the project's own already-proven
  fix (4-decimal `pathSignature`) instead of declining to pin.
- `md5PathsAll` (9-decimal, same-run only) is kept for legs that never cross
  a commit/architecture boundary — leg 1 above, and every other T2–T10 same-
  run comparison in the file (unrelated to this follow-up; explicitly out of
  scope per the brief, and none of those legs are vacuous — they compare two
  values computed in the same process on the same run).
- Doc comment above T1 rewritten to describe the new two-leg oracle and why,
  including a **"RE-PIN ONLY WITH PROOF"** instruction on `EXPECTED_T1`
  (mirrors the plan's own T1 comment convention and the audit protocol's
  "never re-pin a fingerprint without proof in the commit body" rule).

## Non-vacuity proof (mutation, per the brief)

Built a scratch export of the **current worktree including this uncommitted
test-file change** (not just `575f886d`, which predates it) via
`git stash create` (non-destructive — no entry added to `git stash list`,
worktree untouched throughout) + `git archive <stash-tree> | tar -x`, then
symlinked `node_modules`:

```
STASH_SHA=$(git -C <worktree> stash create)
git -C <worktree> archive "$STASH_SHA" | tar -x -C /private/tmp/claude-501/scratch-W38b
ln -s <worktree>/node_modules /private/tmp/claude-501/scratch-W38b/node_modules
```

In the scratch copy only, mutated `scene3d.js`'s absent-key fallback default
from 3 to 2 — the narrowest possible "change the default" mutation, touching
only the literal `finite(styleParams.facetMinRulings, FACET_MIN_RULINGS)`
fallback argument used when the style param is absent, leaving every
explicit value (including explicit `facetMinRulings: 3`) untouched:

```js
finite(styleParams.facetMinRulings, 2) /* W-38b mutation: default changed 3->2 */
```

Ran T1 in the scratch copy: **16 of 60 cases failed**, all on the new pinned-
fingerprint leg (`expected '<mutated-hash>' to be '<pinned-hash>'`) — the
44 cases that didn't fail are exactly the primitives/densities T5's own
inertness roster says the grant never fires for (`sphere` never enters
`faceHatchLines`; `d=220` is above where the grant fires at all), so their
absent-key output is identical regardless of what the fallback default is —
consistent, not a gap in the mutation's coverage. This is the concrete,
reproducible demonstration that the new leg is load-bearing: a real default
regression trips it. Contrast with the removed leg, which — had this same
mutation been committed as the new `HEAD` — would have had `preFixV` re-read
from the *same* mutated `HEAD`, and the comparison would have passed
vacuously, silently. Scratch dir removed after the run
(`rm -rf /private/tmp/claude-501/scratch-W38b`); nothing outside it was
touched.
