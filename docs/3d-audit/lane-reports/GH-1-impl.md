## Task 1 — harden scripts/audit/scene3d-before-after.js

Two new enforcement mechanisms, both scoped to `report.json`-backed cards only
(handoff-unit cards, which have no `report.json`/exceptions mechanism, keep
their old plain "byte-identical" badge unchanged):

**(a) After-path containment (hard refusal).** `checkAfterPaths()` requires
every `after` entry to start with `after/<dirName>/` (dirName = the card's own
physical directory under `after/`). Any violation is collected into
`fatalErrors`; `main()` prints `REFUSED: N ... violation(s) — index.html was
NOT written:` with one line per `card "<id>" ... after-cell "<path>" does not
start with "after/<dirName>/"`, then sets `process.exitCode = 1` and returns
**before** touching `index.html`. This replaces the previous soft
warn-and-drop behavior for `shots/`-prefixed entries (which only handled one
special case and rendered the rest of a broken report anyway).

Verified with a scratch copy of the whole gallery
(`/private/tmp/.../scratchpad/ba-test/`): injecting a bad `after` entry into
`after/W-10/report.json` produced exit code 1, named the exact card and cell,
and left `index.html` byte-identical to the pre-run version (md5-verified) —
the refusal is total, not partial. Scratch copy deleted after the check.

**(b) Byte-identity WARN + badge.** `report.json` may now declare
`"identical_exceptions": { "<after-cell-basename>": { "identical": true,
"reason": "..." } }`. `renderPairsTable()` (now taking an `opts` object
instead of positional args) checks every identical before/after pair against
this map when `opts.enforce` is true (report cards only): an exempted pair
gets `<span class="pill identical" title="<reason>">byte-identical
(explained)</span>`; anything else gets a new warn-colored
`identical-unexplained` pill reading `byte-identical — UNEXPLAINED`, and its
`{card, cell}` is pushed into `stats.unexplainedIdentical`. `main()` prints one
`WARN: N byte-identical ... pair(s) with no "identical: true" + "reason"
exemption` line plus one `card "..." cell "..."` line per violation, and the
summary paragraph in the rendered page now appends a
"N UNEXPLAINED byte-identical pair(s) (see WARN in console output)" clause.
Nothing is silently dropped — the build still succeeds (non-fatal), matching
the brief ("print a WARN ... do not silently pass", no exit-code requirement
for this one, unlike (a)).

Running the real gallery after both hardening changes surfaced **47
pre-existing unexplained byte-identical pairs** across W-01-M1, W-15, W-15b,
W-19, W-20, W-21, W-27 (full list in the console WARN — not reproduced here).
These are new information the hardening was built to surface; annotating each
one with `identical_exceptions` is outside GH-1's scope (only W-10's overwrite
and the before-vs-before pointer bug were the named findings) and is called
out below as an open follow-up.

Output format otherwise unchanged: same pipeline order, same
`ba-tabbar`/pane wrapping, same idempotency guarantee.
